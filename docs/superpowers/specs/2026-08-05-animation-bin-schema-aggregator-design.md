# Animation BIN Schema Aggregator — Design

**Date:** 2026-08-05
**Status:** Approved

## Problem

Animation BINs (`DATA/Characters/{Champion}/Animations/*.bin`) are the least documented
BIN family in the ecosystem. Flint has no reference for them: `flint-bin/src/animask.rs`
covers `mMaskDataMap` weights and nothing else.

The format is extremely repetitive. A real dump (Evelynn `Skin0.bin`, 139 KB, 1200 lines)
contains only **17 distinct classes**, and most instances of a class are identical —
677 `TimeBlendData`, 171 `TransitionClipBlendData`, 64 `AtomicClipData`. What varies is
which *optional* fields an instance carries: of the 64 `AtomicClipData` instances, some
have `mFlags`, some have `mEventDataMap`, all have `mAnimationResourceData`.

So the whole format compresses to one merged block per class — every field any instance
ever carried, in one place. Small file, complete picture.

## Goal

A reference artifact: a compact `.ritobin` file with one superset block per animation
class, generated by scanning a League install. Nothing consumes it at runtime; it is read
by hand while modding.

Explicitly **not** in scope: no editor UI, no autocomplete, no templates, no validation,
no runtime loading of the file.

## Approach

A fourth schema aggregator alongside the three that already exist
(`champion_schema.rs`, `troybin_schema.rs`, `tft_schema.rs`). New file
`src-tauri/src/commands/league/animation_schema.rs`, structurally a clone of
`champion_schema.rs`.

Field merging is already solved: `process_class` keys a `ClassSchema` by class hash and
unions field names across every instance encountered, recursing into nested
pointer/embed/list/map values via `collect_nested`. That *is* the "one `AtomicClipData`
with every field ever seen" behaviour — it needs no new code, only pointing at animation
bins.

### Deltas from `champion_schema.rs`

**1. Category filter.** `BinCategory::Animation` instead of `BinCategory::LinkedData`.
`classify_bin` (in `flint-bin/src/concat.rs`) already recognises the animation path
shape, so this is a single match arm. The Champions WAD walk, `read_bin` call, size and
magic guards, and failure counting are unchanged.

**2. Class-diverse map sampling.** `champion_schema`'s `render_map` takes the first
`SAMPLE_LIMIT_COMPLEX` entries of a map. In an animation bin `mClipDataMap` holds ~64
clips and the first three are all `AtomicClipData`, so `SelectorClipData`,
`SequencerClipData`, `ConditionFloatClipData` and `ConditionBoolClipData` would be
aggregated into the schema map but never rendered anywhere in the output file — they are
only reachable through a sampled value, and no sample points at them.

For animation bins the sampler picks entries by **distinct value class** instead: walk
the map, keep an entry only if its value's class hash has not been seen in this map yet,
up to a cap. `mClipDataMap` then renders one of each clip kind and `mEventDataMap` one of
each event kind:

```
mClipDataMap: map[hash,pointer] = {
    "Attack1"  = AtomicClipData { ... }
    0x89bfcf3a = SelectorClipData { ... }
    "KnockUp"  = SequencerClipData { ... }
    0xa9f4ff86 = ConditionFloatClipData { ... }
    0xfe07b16b = ConditionBoolClipData { ... }
}
```

The cap is higher than `SAMPLE_LIMIT_COMPLEX` (8) because the point is coverage, not
brevity — but distinctness bounds it naturally: a map of 677 identical `TimeBlendData`
still renders one entry.

Lists keep the existing first-N behaviour. Animation lists (`mClipNameList`,
`mWeightList`, `mSelectorPairDataList`) are homogeneous, so class-diversity buys nothing
there.

**3. Blend-key rendering.** `mBlendDataTable` is `map[u64,pointer]` whose key packs two
FNV1a clip hashes — source in the high 32 bits, destination in the low 32. Rendered as a
plain `BinValue::U64` it is a meaningless 20-digit integer. `rs_bin::blend` already
provides `BlendKey`, `BLEND_DATA_TABLE`, `BLEND_KEY_FIELDS` and `is_blend_key_field` for
exactly this, and `rs_bin`'s own text printer uses them under
`TextOptions { blend_keys: true }`.

`render_map` therefore takes the enclosing field's name hash. When
`is_blend_key_field(name_hash)` holds, each `u64` key is split into its two halves, each
half resolved through the hash mapper, and printed as `"Run" -> "Death"` (falling back to
`0x…` per half when unresolved) — matching how the same table reads in a real ritobin
dump.

**4. Output surface.** Writes `animation-bin-schema.ritobin` next to the hash dir.
Progress event `animation-schema-progress`, stats struct `AnimationSchemaStats` (same
shape as `ChampionSchemaStats`), command `aggregate_animation_bin_schema`.

Everything else — `describe_type`, `kind_str`, `fmt_f32`, `escape_str`,
`render_class_block`, the recursion guard, the `#`-comment header, the
`#PROP_text` / `type` / `version` / `entries` envelope — is carried over unchanged, so
the output opens in Flint's BIN editor like any other ritobin text.

## Components

| Unit | Responsibility |
|---|---|
| `animation_schema.rs` | Scan, aggregate, render, write. Self-contained, mirrors its three siblings. |
| `commands/league/mod.rs` | `pub mod animation_schema;` |
| `main.rs` | Register `commands::animation_schema::aggregate_animation_bin_schema` |
| `lib/api/dev.ts` | `aggregateAnimationBinSchema` + `AnimationSchemaStats` |
| `lib/api/core.ts` | Error string for the command |
| `SettingsModal.tsx` | Fourth button in the dev schema section, reusing `SchemaProgressView` / `SchemaResultView` |

## Data flow

League install path → walk `Game/DATA/FINAL/Champions/**.wad.client` → per WAD, bulk-resolve
the chunk TOC through LMDB → keep chunks whose resolved path classifies as
`BinCategory::Animation` → `read_bin` → for each entry, `process_class` merges its fields
(and every nested class) into the global `HashMap<u32, ClassSchema>` → after all WADs,
render one entry per root class into ritobin text → write to disk → return stats.

## Error handling

Matches the siblings exactly. A WAD that fails to open is logged and skipped. A chunk that
fails to decompress, is not `PROP`/`PTCH`, exceeds `MAX_BIN_SIZE`, or fails `read_bin`
increments `bins_failed` and is skipped. A missing Champions directory is the one hard
error (returned to the caller with a message naming the expected path). A missing LMDB
env degrades to unresolved `0x…` names rather than failing — the file is still useful.

## Testing

Unit tests inside `animation_schema.rs`, following the pattern used elsewhere in the
codebase (pure helpers tested against synthetic `BinValue` trees, no League install
required):

- Class-diverse sampling keeps one entry per distinct value class and drops repeats.
- Class-diverse sampling on a map of identical classes yields exactly one entry.
- A blend key round-trips: `(src_hash, dst_hash)` packed into a `u64` renders as
  `"src" -> "dst"` when both resolve, and `0x…` per half when they do not.
- `is_blend_key_field` gates the special rendering — a non-blend `map[u64,…]` still
  renders plain integer keys.

Manual verification: run the aggregator against a live install and confirm the output
contains `AnimationGraphData` with all four maps, and that `mClipDataMap` shows more than
one clip class.

## Non-goals

- No editor UI, autocomplete, insert-templates or validation.
- No runtime consumption of the generated file.
- No changes to `rs_bin` — `blend.rs` already exposes everything needed.
- No new BIN parsing. `read_bin` and `classify_bin` are used as-is.
